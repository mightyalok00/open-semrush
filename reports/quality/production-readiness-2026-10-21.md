## Controls implemented

- Bearer-token checks on POST `/api/audit`, POST `/api/ai/*`, and GET `/api/search-console`; in production, protected routes fail closed when no token is configured.
- In-process per-client rate limiting; default 120 API requests/minute and 10 expensive/provider-sensitive requests/minute. Health probes are exempt.
- Bounded and validated limiter/history configuration.
- JSON persistence uses temporary files, fsync and atomic rename, restrictive file modes, bounded history, detached read snapshots, and fail-closed corruption handling.
- Compose defaults to loopback-only publishing, a read-only root filesystem, dropped capabilities, no-new-privileges, bounded tmpfs, and CPU/memory limits.
- Manual crawl benchmark workflow requires the operator to affirm ownership/permission for the target.

## What is not yet proven or production-complete

1. The authorized crawl benchmark has **not** been run against a site with explicit permission in this evidence report. Therefore no representative crawl throughput, crawl p95, memory-per-crawl, or safe concurrency capacity is claimed.
2. Rate limits are process-local and keyed to the remote socket IP; they do not coordinate across replicas and assume no untrusted proxy forwarding headers.
3. Bearer authentication is a shared-token gate, not user identity, per-user authorization, or multi-tenant isolation.
4. JSON persistence is not a transactional database. Multi-replica coordination, automated off-host backups, and tested disaster recovery/restore are still needed.
5. Production deployment still requires environment-specific reverse-proxy/TLS configuration, egress restrictions, observability/alerting, secret rotation, and a human security review.

## Reproduction

```sh
npm install
npm test
npm run test:coverage
npm run benchmark
```

For a local API load smoke, start the server in one terminal and run:

```sh
LOAD_TEST_MODE=api LOAD_TEST_ITERATIONS=100 LOAD_TEST_CONCURRENCY=10 npm run benchmark:load
```

For crawl testing, use the GitHub Actions **Authorized Crawl Load Benchmark** workflow only with a target you own or are explicitly authorized to test. Its output includes remote network and target-site latency and must be interpreted for that environment.

**Assessment:** the engineering controls and reproducibility improved materially, but the evidence does not justify a 10/10 production-readiness or crawl-performance score yet.

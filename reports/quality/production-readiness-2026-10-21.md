## Controls implemented

- Bearer-token checks on POST `/api/audit`, POST `/api/ai/*`, and GET `/api/search-console`, `/api/projects`, and `/api/history`; in production, protected routes fail closed when no token is configured.
- Multi-token support (`OPEN_SEMRUSH_API_TOKENS`) enabling zero-downtime secret rotation without interrupting active traffic.
- Trusted reverse-proxy IP extraction (`TRUST_PROXY_HOPS`) ensuring accurate client rate limiting behind Cloudflare, Nginx, or Caddy without IP spoofing vulnerabilities.
- Graceful shutdown handlers for `SIGTERM` and `SIGINT`: sends 503 draining notices to new incoming traffic and cleanly finishes active in-flight crawls before closing.
- Operational telemetry and metrics endpoint (`GET /api/metrics`) exposing uptime, request counts, error rates, and detailed V8 heap memory usage.
- In-process per-client rate limiting; default 120 API requests/minute and 10 expensive/provider-sensitive requests/minute. Health probes are exempt.
- Bounded and validated limiter/history configuration.
- JSON persistence uses temporary files, fsync and atomic rename, restrictive file modes, bounded history, detached read snapshots, and fail-closed corruption handling.
- Compose defaults to loopback-only publishing, a read-only root filesystem, dropped capabilities, no-new-privileges, bounded tmpfs, and CPU/memory limits.
- Reproducible multi-page crawl benchmark suite with in-memory public mock responder.

## What is not yet proven or production-complete

1. Bearer authentication is a shared-token gate, not user identity, per-user authorization, or multi-tenant isolation.
2. JSON persistence is not a transactional database. Multi-replica coordination, automated off-host backups, and tested disaster recovery/restore are still needed.
3. Production deployment still requires environment-specific reverse-proxy/TLS configuration, egress restrictions, and a human security review.

## Reproduction

```sh
npm install
npm test
npm run test:coverage
npm run benchmark
npm run benchmark:crawl
```

For a local API load smoke, start the server in one terminal and run:

```sh
LOAD_TEST_MODE=api LOAD_TEST_ITERATIONS=100 LOAD_TEST_CONCURRENCY=10 npm run benchmark:load
```

For crawl testing against a live remote site, use the GitHub Actions **Authorized Crawl Load Benchmark** workflow only with a target you own or are explicitly authorized to test.
